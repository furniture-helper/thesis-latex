Here, we can see that nearly 60\% of the total cost is attributed to the distributed web crawler, which is expected given that it is the most resource-intensive component of the system.
The database also incurs a high proportion of the total cost, which is expected given that it is a component that is shared across all modules of the system.
A few modules of the system are not included in this cost analysis, as they are either part of the development process, are one-time costs (e.g., model training), or their costs are negligible (e.g., the web application).
\begin{itemize}
    \item The data labeller module is not included as it is entirely hosted on AWS Amplify, which is expensed based on usage and is not a significant cost contributor.
    \item The product matching module is not included as it is a one-time cost for model training, and the inference in a one-time operation which was conducted on a local machine.
    \item The proof-of-concept web application is not included as it is entirely hosted on AWS Amplify, and AWS Lambda, which are expensed based on usage and are not significant cost contributors.
\end{itemize}

\subsection{One-time costs}\label{subsec:one-time-costs}
These are the costs that are incurred during the development phase of the system, and are not recurring costs.
These are generally the costs associated with model training and hyperparameter tuning.
These are generally highly variable, and depend on the size of the dataset, the complexity of the model, and the number of hyperparameter tuning iterations.
All three models were trained/fine-tuned on AWS SageMaker using Hyperparameter tuning jobs, and the cost of the last three training runs for each model is summarized in Table~\ref{tab:one-time-costs}.
